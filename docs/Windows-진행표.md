# Windows 개발 진행표

기준: 2026-10-03 개발 재개. 현재 Mac 운영 앱 0.7.2는 사용자가 정상 사용 중인 기준 앱이다. Windows 개발·검수의 미완료를 운영 Mac의 결함으로 해석하지 않는다.

## 완료 상태를 읽는 방법

‘코드 있음’, ‘Mac에서 Windows용 코드 검사’, ‘실제 Windows 자동검사’, ‘Windows 설치본 사용자 검수’는 서로 다른 단계다. 과거 검사는 해당 소스의 증거로 보존하며 최신 후보에 자동 이월하지 않는다. 아래 표는 전체 완료 선언이 아니다.

| 사용자 작업 | 현재 구현과 근거 | 실제 Windows 최신 후보에서 남은 확인 |
|---|---|---|
| PDF·이미지 열기·페이지별 편집 | Workspace·Qt UI·PDF 기하·미디어 검사 코드 있음 | Explorer 혼합 입력, 200쪽 경계, 회전/crop·한국어·배율 |
| 가리기·그리기·레이어·Undo | 편집 엔진·렌더러·내부 Qt 검사 있음 | 잠금·순서·미저장 편집 보존 및 실제 출력 |
| 프로젝트 저장·재열기 | v1/v2/v3 저장·검증 코드 있음 | 프로젝트 드롭, 원본 경로 재연결, Mac과 양방향 왕복 |
| 영상 표시·재생·오디오 | canonical transport, PCM 재생 계획, Qt 오디오 연결 코드 있음 | 실제 Windows 장치·오디오 형식·시간 경계·탐색·취소 |
| 영상 추적·내보내기 | 추적·출력 코드와 합성 자료 검사 있음 | 실제 Windows 코덱의 길이·프레임 시각·소리·대표 장면 |
| 배포용 실행 파일 | PyInstaller launcher·빌드 스크립트 있음 | 실제 frozen EXE에서 보조 프로세스 시작·종료·창 중복 부재 |
| 설치·재배포 | 버전별 설치 스크립트·의존성 입력 검증 있음 | 실제 DLL·라이선스 자료·설치·제거·서명 상태·패키지 해시 |
| 공개 | 기존 개발 브랜치 공개 이력 있음 | 검수된 Windows 설치 파일·안내·소스·최종 다운로드 해시 |

오래된 상태 문서의 ‘오디오 UI 연결 없음’, ‘v3 연결 보류’ 등의 문장은 현재 코드와 다시 대조해야 한다. 연결 코드가 존재한다는 것만으로 실제 장치 재생이나 프로젝트 호환이 검증된 것은 아니다.

## 이번 수정 묶음

1. 설치 파일 진입점이 보조 프로세스 분기보다 먼저 Qt를 읽는 문제.
2. `.bluraction` 프로젝트 드롭을 이미지 입력으로 보내는 문제.
3. 잠긴 레이어의 순서 변경을 허용하는 문제.
4. 최종 패키지 검토 기록에 의존성별 판정이 빠져도 통과할 수 있는 문제.
5. 패키징 명령의 상대 Python 경로가 작업 폴더 변경 뒤 달라지는 문제.
6. 여러 레이어를 함께 앞뒤로 옮길 때 내부 순서가 뒤집히는 문제.

각 수정은 수정 전 반례, 수정 후 필요한 검사, 독립 검토를 연결한다. 상세한 로컬 실행 기록은 `qa-20261003/windows-development-start/`에 보관한다. 이 폴더는 공개 소스에 포함하지 않는다.

위 여섯 문제의 수리를 반영했다. 최종 입력에서 launcher 3개, 패키징 입력 검증 30개, 새 프로젝트/레이어 회귀 10개, 기존 편집 엔진 50개, 기존 UI 47개가 여러 실행으로 통과했다. 합계 140개는 중복을 제외한 해당 검사 범위이며, 전체 기능 검사나 실제 Windows 통과 수가 아니다. 수정 전 실패와 중간 실행 기록도 보존했다. PowerShell의 Python 경로 고정은 소스 검토만 완료했고 실제 Windows 명령 실행은 남아 있다.

설치 진입점 수리는 [PyInstaller의 다중 프로세스 안내](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#multi-processing)에 맞춰 GUI를 읽기 전에 자식 프로세스 분기를 처리한다. 프로젝트 드롭 검사는 내부 Qt 객체를 사용하며 실제 Explorer 입력을 대신하지 않는다. 패키징 검사는 전체 의존성에 대한 검토 기록 누락을 차단하지만 법적 적합성을 자동 인증하지 않는다.

## 다음 실제 Windows 확인 순서

1. 사용할 PC의 OS·CPU·설치 제한과 검수 가능한 시점을 확인한다.
2. 로컬 수정 묶음을 검토한 뒤 정확한 소스 버전으로 Windows 자동검사를 한 차례 수행한다. 실패하면 해당 원인을 먼저 진단한다.
3. 비공개 후보를 만들고 실제 포함 파일·의존성·해시를 확인한다.
4. 개발 도구가 없는 Windows에서 설치→열기→편집→프로젝트 저장→재실행→출력을 검수한다.
5. Windows 영상·Mac 프로젝트 왕복 검수와 독립 검토를 완료한 뒤 공개한다.

이번 재개에서는 기존 Mac 앱의 빌드·실행·교체를 하지 않는다. 컴퓨터 사용 권한이나 OS 입력 자동화는 사용하지 않는다. GitHub 실행은 반복 알림 방지를 위해 변경 묶음 단위로 관리한다.
