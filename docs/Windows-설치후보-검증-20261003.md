# Windows 설치 후보 제작 기록

학교 Windows 11 x64 PC에 전달할 설치본을 준비하는 기록이다. Mac 운영 앱 0.7.2/build18은 교체하지 않는다. 컴퓨터 사용 권한이나 OS 입력 자동화는 사용하지 않는다.

## 실행 파일 묶음 제작 성공

[Windows 실행 37106551917](https://github.com/piman-code/bluraction/actions/runs/37106551917)은 커밋 `8884963b614730a4c911ef426e10201177ed7712`로 실행했다. Windows 2025 x64, CPython 3.14.7에서 실제 입력 파일을 확인하고 PyInstaller로 `0.8.0-dev1-ci37106551917-1` 후보를 만들었다.

- 같은 입력의 전체 자동검사: 36묶음 534개 통과. 별도 HEIF/PDF 9개 검사는 겹치므로 더하지 않는다.
- 생성된 묶음: 전체 888파일, 네이티브 238파일. 모두 AMD64로 관측했다.
- 네이티브 191파일은 입력 wheel 또는 Python 런타임 파일과 SHA-256이 정확히 일치했다.
- 47파일은 아직 입력 제공자와 연결되지 않았다. 생성한 제품 EXE 1개와 Windows 런타임·OpenSSL DLL 46개다. 빌드 도구의 실제 수집 경로를 확인해야 하며 파일명만으로 출처를 확정하지 않는다.
- 후보의 DLL이나 EXE는 공개하지 않았다. GitHub에 보관한 것은 파일 목록·해시·검사 보고서다.

| 기록 | SHA-256 |
|---|---|
| BlurAction.exe | `dc0027c89efc27931f814c23c9ff8c193b1c3fbe222008cd372b8968bbdbee90` |
| 소스 ZIP | `d08b9fc7dae3cc891b36df5286d1186c560fd61a325247a3480ce9acc67c3886` |
| 실제 입력 기록 | `b4ccfd27701148bea888013d6859cb921d1193134f851a8f321dd4bafa00e560` |

이 결과는 실행 파일을 묶어 만들었다는 증거다. 생성된 EXE 자체의 실행, 설치·제거, 서명, 학교 PC 사용 검수의 통과 증거는 아니다. 이후 소스를 바꾸면 해당 후보를 새로 만들고 필요한 검사를 수행한다.

## 다음 확인

1. 개발 환경 경로를 제거한 빈 작업 폴더에서 실제 EXE를 실행한다. 합성 PDF·이미지 편집, 프로젝트 저장·재열기, 모든 출력 페이지의 픽셀, 실제 영상 디코더 자식 프로세스의 시작·종료를 확인한다.
2. 실제 수집 경로를 기준으로 아직 연결되지 않은 DLL 출처를 확인한다. 포함 라이브러리의 고지·대응 소스·빌드 자료를 맞춘다. 자료가 있다는 것과 재배포 검토가 끝났다는 것을 구분한다.
3. 검토된 묶음으로 설치 EXE를 만들고 해시·서명 상태·설치 및 제거를 확인한다.
4. 학교 PC에서 설치→파일 열기→가리기→저장→재실행→내보내기를 사용자가 확인한다. Explorer 드롭, 파일 선택 창과 실제 오디오도 이 단계에 포함한다.

검수용이라는 이유로 라이선스 검토를 생략하거나 기존 `pending` 기록을 일괄 승인하지 않는다. CLI 합성 검사가 실제 사용자 조작을 대신했다고 기록하지 않는다.
