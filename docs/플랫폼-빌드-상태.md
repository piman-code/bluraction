# 플랫폼 빌드 상태

## 현재 기준

- 운영 Mac은 0.7.2/build18, macOS14 이상 arm64에서 검수한 후보이다.
- 기존 Mac 검수 변경은 로컬 `a2ead73`, Windows·공통 초기 구현은 `299c22a`에 보존했다. 후속 Mac 수리는 `eb4b151`에 기록했다. Windows 후속 수리는 로컬 `7e40a14`에 기록했다. 문서/CI는 소스 준비 상태이며 GitHub로 전송하지 않았다.
- Windows는 `platforms/windows/bluraction/`의 별도 Qt 어댑터이다. 기존 Mac
  `Sources/BlurAction/`와 `scripts/build_app.sh` 경로를 유지한다.
- `shared/`는 v1/v2 데이터 계약·경로 재연결·합성 자료이다. 앱 구현과 렌더러는
  각 플랫폼의 책임이다. Mac에서 Qt 검사가 통과해도 Windows 검수로 표기하지 않는다.

## Mac 후보

```sh
python3 scripts/verify_mac.py
# 필요한 한 묶음만 검사할 때:
python3 scripts/verify_mac.py --suite PortableProjectCompatibilityTests
./scripts/build_app.sh --build-only --no-install
```

후보는 `.build/BlurAction.app`에 생긴다. `/Applications/BlurAction.app`이나
루트의 이전 `BlurAction.app`을 이 명령으로 교체하지 않는다. 빌드 후 후보를
별도 이름으로 복사하고 버전·서명·파일 manifest·출력을 그 후보로 검수한다.
현재 소스18묶음138 내부 회귀와 별도 AppKit 검수 뒤 만든 후보는 `BlurAction-0.8.0-20261002-053145.app`이다. 이전 후보의 통과를 옮기지 않았으며 새 빌드 입력·바이너리·서명 manifest를 별도로 기록했다. 현재 ad-hoc 서명이며 Developer ID 서명·공증 통과 증거는 없다. 실제 Finder/파일 패널·깨끗한 OS 사용자 실행도 남는다.

## Windows 개발·패키징 준비

아래 명령은 **Windows에서 아직 실행하지 않은 재현 절차**다. 현재 로컬
Mac에는 PowerShell/Inno compiler가 없어 새 `.ps1`을 파싱·실행하지 않았다.
Mac의 Qt 합성 검사 결과는 Windows 패키징·설치·사용 검수 증거가 아니다.
저장소 루트의 Windows PowerShell에서, 이미 승인한 격리 Python과 실제
라이선스 자료 경로를 지정한다. 이 절차는 의존성이나 도구를 설치하지 않는다.

```powershell
$CandidateVersion = '0.8.0-dev1'
$CandidatePython = 'C:\approved-env\Scripts\python.exe'
$CandidateDirectory = Join-Path (Get-Location).Path ".build/windows-packages/$CandidateVersion"
$LicenseMaterials = 'C:\reviewed-candidate\dependency-materials'
$LicenseReview = 'C:\reviewed-candidate\license-review.json'

# 내부 검사: 기존 QT_QPA_PLATFORM 값을 성공/실패 모두에서 복원한다.
$PriorQtPlatform = [Environment]::GetEnvironmentVariable('QT_QPA_PLATFORM', 'Process')
try {
  & $CandidatePython -c "import subprocess,sys; subprocess.run([sys.executable,'-m','unittest','discover','-s','Tests/PortableProjectTests','-v'],check=True,timeout=120)"
  if ($LASTEXITCODE -ne 0) { throw 'Portable tests failed or timed out.' }
  [Environment]::SetEnvironmentVariable('QT_QPA_PLATFORM', 'offscreen', 'Process')
  & $CandidatePython -c "import subprocess,sys; subprocess.run([sys.executable,'-m','unittest','discover','-s','Tests/WindowsAppTests','-v'],check=True,timeout=900)"
  if ($LASTEXITCODE -ne 0) { throw 'Qt/media tests failed or timed out.' }
} finally {
  [Environment]::SetEnvironmentVariable('QT_QPA_PLATFORM', $PriorQtPlatform, 'Process')
}

# 실제 notices/증거가 있어야 새 onedir와 manifest를 준비할 수 있다. ZIP은 만들지 않는다.
./platforms/windows/build_package.ps1 -Python $CandidatePython -Version $CandidateVersion `
  -Destination $CandidateDirectory -LicenseMaterials $LicenseMaterials -PrepareForReview

# 여기서 중단해 dist/BlurAction의 실제 DLL/codec/license를 검수한다.
# exact bundle-manifest.json SHA와 version에 연결된 reviewed record를 작성한 뒤에만 실행한다.
# 기존 onedir를 재빌드하지 않고 같은 bytes로 ZIP을 만든다.
./platforms/windows/build_package.ps1 -Version $CandidateVersion `
  -Destination $CandidateDirectory -LicenseReview $LicenseReview -FinalizeReviewedBundle

# 같은 reviewed bundle로 설치 EXE를 컴파일한다. compiler가 없으면 설치 승인을 먼저 받는다.
# OutputDirectory는 존재하지 않는 새 폴더여야 한다. installer를 실행하는 명령은 아니다.
./platforms/windows/installer/build_installer.ps1 `
  -Bundle (Join-Path $CandidateDirectory 'dist/BlurAction') `
  -BundleManifest (Join-Path $CandidateDirectory 'bundle-manifest.json') `
  -LicenseReview $LicenseReview -Version $CandidateVersion `
  -OutputDirectory (Join-Path (Get-Location).Path ".build/windows-installers/$CandidateVersion")
```

`-PrepareForReview`는 새 출력 폴더를 요구한다. 생성되는 위치는 지정한
`$CandidateDirectory/dist/BlurAction`과 `$CandidateDirectory/bundle-manifest.json`이다.
검수 후 같은 directory를 `-FinalizeReviewedBundle`에 넘긴다. 자료·검수 기록 없이
ZIP/installer gate를 통과시키지 않으며 `license-review.example.json`의 pending
예시는 승인 기록이 아니다. 설치 wrapper의 `-Compiler`는 필요할 때 이미 설치된
ISCC.exe 경로를 지정하는 선택 인자이며 도구를 설치하지 않는다.

실제 `LicenseMaterials`에는 `NOTICE.txt`, `dependencies.json`, 각 의존성의
원문 라이선스와 bundled binary/build 증거가 있어야 한다. inventory의 각 항목은
`id/version/license/redistribution_review/license_files/evidence_files`를 기록한다.

후보를 만들기 전에 지정한 Python의 distribution metadata를 `requirements-dev.txt`와
`installer/requirements-packaging.txt`의 모든 exact pin과 대조한다. 누락·다른 버전은
오류로 중단한다. `-VerifyRuntimeOnly`는 개발 runtime 목록만 검사하며 PyInstaller를
요구하지 않는다. metadata 검사는 설치·native import·라이선스 적합 판정·실제 codec
검수를 수행하지 않으며, 뒤의 실제 PDF/HEIF 검사와 최종 번들 검수를 대체하지 않는다.
Pillow12.3.0은 새 소스 준비 pin이고 실제12.3 runtime/Windows 회귀는 아직 미검증이다.

Qt/PDFium·Python·PyAV/실제 FFmpeg DLL·OpenCV·Pillow·NumPy·PyInstaller와 추가
codec을 exact bundle 대상으로 검수해야 한다. 파일 존재 검사는 재배포 적합성
판정이 아니다. PyAV wrapper 라이선스만으로 FFmpeg의 GPL 구성 요소를 허용하지
않으며, HEIC decoder/encoder도 실제 codec과 조건을 검수하기 전 bundle에 넣지 않는다.
현재 완성된 라이선스 자료와 exact bundle 검수 기록은 없다.

두 스크립트는 숨김 파일을 포함한 전체 파일을 manifest와 대조하고 root·상위
경로·하위 디렉터리/파일의 reparse 경로를 거부한다. ZIP 생성과 ISCC 컴파일
전후에 bundle 파일 지문 및 manifest/review bytes를 다시 확인한다. 변경되면
결과를 검수 완료로 받아들이지 않는다. 패키징의 내부 검사는 portable 120초,
Qt/media 900초 제한이며 예외에도 기존 `QT_QPA_PLATFORM`을 finally에서 복원한다.

새 의존성 설치는 별도 승인한 격리 환경에 한정한다. Windows용 고정 wheel과
실제 포함 DLL, PyInstaller/Inno 존재·버전을 확인해야 한다. 로컬 Mac에서 준비한
소스와 스크립트만으로 Windows 설치·실행을 선언하지 않는다. 설치 EXE 준비
코드는 있지만 실제 Windows 컴파일·깨끗한 사용자 설치·시작 메뉴 실행·Explorer
drop·출력 검수·코드 서명·HEIC codec 검증은 아직 남아 있다. 개발 실행은 같은
승인한 interpreter로 `& $CandidatePython -m platforms.windows.bluraction`을 사용한다.

실제 지원 완료 표기는 설치·사용 검수를 통과한 OS와 아키텍처에 한정한다.
Windows11 x64를 우선 검증할 계획이며 Windows10·ARM64·Intel Mac은 별도
검증 전 지원 완료로 선언하지 않는다. 기존 미디어 형식은 조용히 제외하지
않고 구현/라이선스/검증 차이를 기능표에 남겨 사용자 결정이 필요한 경우 제시한다.

## 공개 경계

QA 전체 폴더, `.build`, 개인 자료, 원본, 백업은 공개하지 않는다. 공개 승인
직전에 실제 Git 전송 목록과 릴리스 파일을 확인하고 비밀값·민감정보 검사를
다시 한다. 최종 브랜치·커밋·버전·설치 파일·SHA-256을 보여 준 뒤 승인받고
push/PR/merge/Release를 실행한다. 이 문서와 스크립트를 준비한 것만으로
패키지 검수나 최종 Goal 완료를 뜻하지 않는다.
