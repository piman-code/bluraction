# BlurAction

macOS에서 영상·이미지의 원하는 부분을 **블러·모자이크·단색**으로 가리고, 선·도형·화살표·글자를 그려 넣는 로컬 앱입니다. 원본은 수정하지 않고 별도 파일로 저장합니다. 영상에서는 가린 영역과 그림을 **움직임에 맞춰 따라가게** 직접 기록하거나 **자동 추적**으로 기록하고, 여러 항목을 **그룹**으로 묶어 함께 옮기며, 지우개도 **시간을 따라** 적용됩니다. 모든 항목은 **레이어 목록**에서 이름·보이기·잠금을 관리하고, 작업은 **프로젝트 파일**로 저장해 이어 하거나 다른 영상에 템플릿처럼 적용할 수 있습니다.

현재 Mac 후보의 검수 대상은 macOS 14 이상 arm64입니다. 소스 빌드·내부 검증에는 Swift Command Line Tools가 필요하며, 외부 Swift 패키지는 사용하지 않습니다. 현재 저장소에는 같은 프로젝트 형식을 읽는 Windows Qt 개발 후보도 있습니다. Windows 실제 실행·설치 및 양방향 호환 검수는 진행 중이며, 아직 검수 완료된 Windows 릴리스는 없습니다.

개발 소스는 `codex/multipage-document-blur` 브랜치에서 공개하고 있습니다. [첫 실제 CI](https://github.com/piman-code/bluraction/actions/runs/36953462804)는 portable 검사 통과 후 Mac 검사 도구 준비와 Windows 파일 지문 검사에서 실패했습니다. 수정 후 결과와 필수 미검증 항목은 아래 상태 문서에 구분합니다.

- [플랫폼별 빌드·패키징](docs/플랫폼-빌드-상태.md)
- [현재 검증 상태](docs/검증-상태.md)
- [Windows 한국어 사용 안내 초안](docs/Windows-사용-안내.md)
- [실제 OS 사용자 검수](docs/실제-OS-검수.md)
- [Mac 후보 설치·복구](docs/Mac-설치와-복구.md)

## 빌드와 실행

```bash
./scripts/build_app.sh --build-only --no-install
open .build/BlurAction.app
```

위 명령은 `.build/BlurAction.app` 후보만 만듭니다. 운영 설치를 교체하려면 검수한 후보와 복구본을 먼저 확인하세요. 옵션 없는 `./scripts/build_app.sh`는 `.build/BlurAction.app`을 검증한 뒤 프로젝트 루트의 `BlurAction.app`과 `/Applications/BlurAction.app`을 같은 결과로 갱신합니다. 그래서 Spotlight나 Launchpad로 열어도 최신 빌드가 실행됩니다. 이전 앱은 지우지 않고 `.build/backups/`로 옮겨 보존합니다. `/Applications`에 다른 앱이 같은 이름으로 있으면 건드리지 않습니다.

- `./scripts/build_app.sh --no-install`: `/Applications`는 그대로 두고 루트 앱만 갱신
- `./scripts/build_app.sh --build-only`: `.build/BlurAction.app` 후보만 생성

실행 중이던 앱은 종료한 뒤 다시 열어야 새 버전이 적용됩니다.

앱 아이콘 원본은 `Resources/AppIcon.png`입니다. 아이콘만 다시 만들려면 `./scripts/build_icon.sh`를 실행하세요. 현재 Command Line Tools에서 `iconutil`이 유효한 iconset을 거부하는 경우 Pillow(`python3 -m pip install Pillow`)로 ICNS를 묶어 다시 읽어 확인합니다.

## 사용

1. **열기(⌘O)** 또는 영상·이미지를 캔버스로 드래그합니다. Finder의 ‘다음으로 열기’도 지원합니다.
2. 오른쪽 사이드바에서 도구를 고릅니다: **블러(B) / 그리기(D) / 지우개(E)**.
3. **블러** 도구에서 **사각형 / 원 / 점찍기 / 자유** 중 하나로 가릴 영역을 만듭니다. 점찍기는 첫 점 클릭 또는 Enter로 닫고, Esc로 취소합니다.
4. **가리기 방식**을 고릅니다.
   - **블러**: 흐리게. 강도 0은 적용하지 않습니다.
   - **모자이크**: 픽셀 블록. 크기 슬라이더가 블록 크기입니다.
   - **단색**: 고른 색으로 완전히 덮습니다. 색은 색상 칸이나 **스포이드**로 고릅니다.
   **경계 부드럽게**는 세 방식 모두에 적용됩니다. 값은 원본 픽셀 기준이라 창 크기가 바뀌어도 효과가 같습니다. 방식을 바꾸면 선택한 영역에 적용되고, 다음에 만들 영역의 기본값도 됩니다.
5. 영역 내부를 드래그해 옮기고, 모서리·변 핸들로 크기를 바꿉니다. Shift는 정사각형/정원입니다. 방향키는 1pt, Shift+방향키는 10pt, 선택 영역의 Command+방향키는 0.1pt 이동합니다. ⌘D는 선택 항목을 복제합니다.
6. **내보내기(⌘E)**로 저장합니다.
   - 이미지: PNG/JPEG/HEIC/TIFF 중 고릅니다. 화질 프리셋은 JPEG/HEIC 압축 품질에 적용되고, PNG/TIFF는 무손실입니다. 기존 파일이나 원본 이름을 고르면 덮어쓰지 않고 오류를 알립니다. 긴 한글 파일명은 저장 가능한 길이로 정리합니다.
   - 영상: MP4 또는 MOV로 저장하며 오디오를 함께 보존합니다. 이름은 `원본이름_blurred`이고, 같은 이름이 있으면 `(1)`, `(2)`를 붙입니다. 진행 중 취소하면 불완전한 결과를 남기지 않습니다. ‘원본’ 화질도 H.264로 다시 인코딩하므로 비트 단위 원본 복사는 아닙니다.

## 여러 페이지 PDF와 이미지 묶음

- **열기(⌘O)**에서 PDF 한 개나 이미지 여러 개를 선택합니다. Finder에서 여러 이미지 또는 PDF를 함께 캔버스에 끌어놓을 수도 있습니다. 영상은 기존처럼 한 파일씩 엽니다.
- 화면 아래 **이전 / 다음**으로 페이지를 바꿉니다. 각 페이지의 가리기, 그리기, 부분·항목 지우기, 레이어, 그룹, 실행취소 기록은 따로 유지됩니다.
- 같은 위치를 한 번에 가리려면 첫 페이지에서 편집한 뒤 **현재 페이지 작업을 모든 페이지에 적용…**을 누릅니다. 다른 페이지의 기존 편집을 대체한다는 확인 후 비율 좌표로 복사합니다. 복사한 뒤에는 페이지마다 따로 수정할 수 있습니다.
- **내보내기(⌘E)**는 새 PDF를 만듭니다. 이미지가 포함된 작업은 이미지별 무손실 PNG도 새 `…_images` 폴더에 만듭니다. 원본 PDF·이미지는 수정하지 않으며 기존 결과 파일은 덮어쓰지 않습니다. PDF 출력은 각 페이지를 이미지로 굳혀 원본 PDF의 검색 가능한 텍스트를 담지 않습니다.
- **프로젝트 저장(⌘S)**과 **프로젝트 열기(⇧⌘O)**는 페이지별 편집을 `.bluraction`에 기록하고 다시 엽니다. 프로젝트 파일에는 원본 파일 자체가 들어가지 않으므로 원본도 함께 보관하세요. 기존 단일 파일 프로젝트도 열 수 있습니다.
- 한 번에 최대 200페이지, PDF당 512MB, 이미지당 128MB, 전체 입력 1GB, PDF 출력 렌더링 총 5억 화소까지 처리합니다. 긴 내보내기는 **취소**할 수 있으며, PDF가 완성된 뒤 이미지별 저장 중 취소하면 이미 만든 결과는 남을 수 있습니다.

내보내기나 자동 추적 중에는 새 파일 열기·드롭을 잠시 받지 않습니다. 작업을 마치거나 취소한 뒤 다른 문서를 열어 주세요. PDF와 이미지를 섞어 열어도 전체 200페이지 제한이 적용됩니다. 긴 파일명으로 만든 프로젝트도 다시 열 수 있으며, 저장 제안 이름과 이미지 결과 폴더명은 접미사를 포함해 저장 가능한 길이로 정리합니다.

이전 버전에서 회전이나 여백 처리로 잘렸던 PDF에 편집을 저장했다면, 프로젝트를 열 때 가림 위치 재확인 안내가 나올 수 있습니다. 원본 PDF를 새로 열어 가림·그림을 확인하고 새 프로젝트로 저장하세요. 기존 프로젝트와 원본 파일은 변경하지 않습니다.

**민감 정보:** 흐림 효과는 화면에서 글자를 가리지만 완전한 비식별화 수단은 아닙니다. 복원 위험을 줄여야 하는 곳은 **단색**과 **경계 부드럽게 0**을 쓰고, 내보낸 모든 페이지를 직접 확인하세요.

사이드바 맨 위에는 원본 크기·형식(영상은 FPS·코덱·비트레이트·길이)·파일 크기가 스크롤 중에도 보입니다. 화질 메뉴 아래에는 선택한 형식·압축 품질 또는 H.264 목표 비트레이트를 표시합니다. 표시한 영상 비트레이트는 인코더 **목표** 값이며 실제 파일의 평균 값과 다를 수 있습니다.

## 그리기·채우기

**그리기** 도구에서 **사각형 / 타원 / 선 / 펜 / 화살표 / 글자**로 가리기와 별개인 선과 도형을 그립니다.

- **글자**: 캔버스를 클릭하면 입력 창이 열리고, 클릭한 곳이 글자의 왼쪽 위가 됩니다. Return으로 **여러 줄**을 쓸 수 있습니다. 크기는 “글자 크기”(선 굵기 슬라이더)로, **글꼴**(시스템·Apple SD 산돌고딕 Neo·명조 등 설치된 글꼴)과 **굵게**, 자막처럼 뒤에 까는 **배경 상자**(반투명·불투명 검정/흰색)를 고릅니다. 글자를 선택한 채 바꾸면 그 글자에 바로 적용됩니다. 더블클릭하면 내용을 고치고, 모서리를 끌면 글자가 상자에 맞춰 커지거나 줄어듭니다.

- **색**: 색상 칸(클릭하면 macOS 색상판과 화면 돋보기가 열림), **스포이드**(영상·이미지에서 클릭한 곳의 색, 단축키 I), 자주 쓰는 색 메뉴 중 편한 것을 씁니다.
- **선 굵기** 1~20, **채우기**(없음 / 반투명 / 불투명): 사각형·타원·펜 도형 안을 같은 색으로 채웁니다. 선은 채우지 않습니다.
- 그린 것을 클릭하면 선택됩니다. 끌어서 옮기고, 모서리의 주황 핸들로 크기를 바꿉니다. 선택한 채 색·굵기·채우기를 바꾸면 그 그림에 바로 적용됩니다.
- Delete 또는 더블클릭으로 지웁니다(글자는 더블클릭하면 고치기).
- 영상에서는 그리기 시작한 시점부터 영상 끝까지 표시됩니다. 표시 구간과 움직임 기록은 블러 영역과 똑같이 다룹니다(아래 참고). 표시 구간 밖에서는 캔버스에 흐린 점선으로만 보이고 내보낸 파일에는 들어가지 않습니다.

## 시간 구간과 움직임 기록 (영상)

영역이나 그림을 선택하면 **적용 시간 (초)**에 시작·끝을 입력하고 **구간 적용**을 누를 수 있습니다. 예를 들어 `2` ~ `5`는 2~5초 동안만 적용됩니다. **영상 전체**로 되돌릴 수 있고 항목마다 따로 설정됩니다. 새 영역·그림은 추가한 시점부터 영상 끝까지 적용됩니다. 우클릭하면 **현재 위치부터 0.5 / 1 / 3 / 5 / 10초**, **영상 전체**, **이동 기록 지우기**, **복제**, **삭제**를 고를 수 있습니다.

**움직임 기록**(사이드바 체크, 기본 켜짐)을 켜 두면, 영상에서 영역이나 그림을 옮긴 시점의 위치가 기록되어 움직이는 대상을 따라갑니다. 방법은 두 가지이고 섞어 써도 됩니다.

- **재생하면서 끌기**: ▶ 또는 캔버스에 포커스를 둔 Space로 재생하고 대상을 따라 끕니다. 재생 중에는 캔버스 왼쪽 위에 **● 움직임 기록 중**이 표시됩니다.
- **멈추고 프레임을 넘기며 옮기기**: 타임라인이나 `,` `.`(약 1프레임), ⌘←/⌘→(1초)로 시점을 옮기고 그 자리에 맞게 끌어 둡니다. 첫 이동은 항목의 시작 시점 위치에서 그 시점까지 부드럽게 이어지고, 이후 옮길 때마다 위치가 추가됩니다. 시작 시점에서 옮기면 처음 위치만 바뀝니다.

기록된 위치 사이는 선형으로 이어지고, 끌기 전에 기다린 구간은 멈춰 있습니다. 선택 항목의 기록 경로는 캔버스에 주황 점선으로, 기록 시점은 타임라인에 주황 눈금으로 보입니다. 목록에는 **이동**으로 표시됩니다.

- **움직임 기록을 끄면** 옮기거나 크기를 바꿀 때 새 위치를 추가하지 않고 기록된 경로 전체가 함께 움직입니다. 이미 따라가게 만든 영역을 통째로 조금 옮길 때 씁니다.
- **위치·크기 정밀 조정**에는 원본 왼쪽 위 기준 픽셀 좌표가 보입니다. 좌표·크기를 입력해 **좌표·크기 적용**을 누르면 끌어서 옮긴 것과 같은 규칙으로 반영됩니다. **현재 위치 기록**은 화면에 보이는 위치를 그 시점에 고정합니다. 가변 프레임률 영상에서 ‘약 1프레임’은 평균 FPS 기준이라 실제 프레임 경계와 다를 수 있습니다.
- 다각형 이동도 기록됩니다. 다각형 꼭짓점 편집은 기본 모양을 수정하고, 그 모양에 기존 위치·크기 기록이 적용됩니다.
- 우클릭의 **이동 기록 지우기**는 현재 위치를 고정 위치로 확정합니다.
- **타임라인에서 직접 고치기**: 선택 항목의 기록 시점(주황 마름모)과 적용 구간(파란 띠)이 타임라인 아래 띠에 보입니다. 마름모를 좌우로 끌면 그 위치의 시각이 바뀌고(앞뒤 기록 사이에서만), 파란 띠의 양 끝을 끌면 적용 구간이 바뀝니다. 띠 밖을 누르면 평소처럼 재생 위치를 옮깁니다.
- **기록 사이 이동**: **◀ 이전 기록 / 다음 기록 ▶** 버튼이나 `<` `>` 키로 선택 항목의 기록 시점으로 바로 갑니다.
- **자동 추적**: 대상에 맞게 영역(또는 그림)을 잡고 선택한 뒤 **선택 항목 자동 추적**을 누르면, 지금부터 항목이 끝나는 시점까지 Apple Vision이 대상을 따라가며 위치를 기록합니다. 블러 영역은 추적된 상자 크기를 따르고, 그림은 크기를 유지한 채 움직임만 따라갑니다. 대상이 가려지거나 사라지면 거기서 멈추고 알려 주며, 진행 중에 **취소**하면 거기까지만 기록합니다. 전체가 ⌘Z 한 번으로 되돌아가므로, 결과가 어긋난 부분은 직접 끌어 고치면 됩니다.
- 작업을 이어 하려면 프로젝트로 저장하세요(아래 참고). 저장하지 않고 다른 파일을 열면 영역·그림과 실행취소 기록이 초기화됩니다.

## 지우개와 전체 삭제

**지우개** 도구에는 두 가지 방식이 있습니다.

- **부분 지우개**: 크기(4~120pt)를 정하고 문지르면 문지른 부분만 지웁니다. 동그란 브러시 테두리가 크기를 보여 줍니다. 대상은 **그림과 블러 모두 / 그림만 / 블러 영역만** 중에서 고릅니다. 블러 영역을 지우면 그 자리는 가려지지 않습니다. 지운 자리는 **그 항목에 붙어 있어서**, 옮기거나 크기를 바꾸거나, 움직임 기록·그룹으로 움직이거나, 겹침 순서를 바꿔도 함께 따라갑니다. 문지를 때 화면에 보이던 항목에만 적용되고, 나중에 만든 항목과 잠긴 레이어는 지우지 않습니다. 우클릭의 **지운 부분 되살리기**로 그 항목의 지운 부분이 모두 돌아옵니다.
- **항목 지우개**: 영역이나 그림을 클릭하거나 문지르면 닿은 것을 통째로 지웁니다. 가리키면 지워질 대상이 빨간 점선으로 표시됩니다(맨 위 하나만).

영상에서는 **지금 시점부터 지우기**(기본 켜짐) 덕분에 중간에 지워도 그 전의 흔적이 남습니다. 3초에서 지우면 3초 전까지는 그대로 보이고 그 뒤부터 지워진 상태가 됩니다. 부분 지우개도 같은 방식으로 지운 시점부터 적용됩니다. 끄면 영상 전체에서 지웁니다.

사이드바 버튼으로 **선택 항목 / 블러 영역 모두 / 그리기 모두 / 모두 지우기**를 할 수 있고, 편집 메뉴의 **모두 지우기…**(⌥⌘⌫)도 있습니다. 전체 삭제는 확인을 거치고 영상 전체에서 지웁니다. 모든 지우기는 ⌘Z로 되돌릴 수 있으며, 한 번의 드래그·문지르기는 실행취소 한 단계입니다.

## 그룹과 겹침 순서

- **그룹**: Shift+클릭으로 여러 항목을 고른 뒤 **그룹 만들기**(⌘G)를 누릅니다. 블러 도구에서는 영역을, 그리기 도구에서는 그림을 Shift+클릭합니다. 도구를 바꿔도 고른 항목은 유지되므로 영역과 그림을 섞어 묶을 수 있습니다. 고른 항목은 보라 점선으로 표시됩니다.
  - 그룹의 한 항목을 옮기면 나머지도 같은 만큼 움직입니다. 영상에서는 움직임 기록도 모두에게 함께 남습니다.
  - 적용 시간을 바꾸면 그룹 전체에 적용됩니다. 선택한 항목의 그룹은 보라 점선 상자와 “그룹” 표시로 보입니다.
  - 그룹의 한 항목 **크기를 바꾸면** 나머지도 그 상자를 기준으로 같은 비율로 커지거나 줄어듭니다(다각형 꼭짓점 고치기는 그 항목만).
  - 그룹의 항목에서 **복제**(⌘D)하면 그룹 전체가 새 그룹으로 복제됩니다.
  - **그룹 풀기**(⇧⌘G)로 풉니다. 잠긴 멤버는 그룹을 옮겨도 움직이지 않습니다.
- **겹침 순서**: 선택한 항목을 **앞으로**(⌘]) / **뒤로**(⌘[) / **맨 앞**(⇧⌘]) / **맨 뒤**(⇧⌘[)로 옮깁니다. 사이드바 버튼과 우클릭 메뉴에도 있습니다. 블러 영역끼리, 그림끼리 순서가 바뀝니다. 그림은 항상 블러 영역 위에 그려집니다.

## 레이어 목록

사이드바의 **레이어 (위가 앞)** 목록에 블러 영역과 그림이 모두 나오며, 위에 있을수록 화면에서 앞에 보입니다. 각 행에는 종류 아이콘, 이름, 적용 구간, **이동**·**그룹** 표시, 👁 **보이기/숨기기**, 🔒 **잠금** 버튼이 있습니다.

- **이름 바꾸기**: 행을 더블클릭하거나 우클릭 → **이름 바꾸기…**. 비우면 자동 이름(예: “블러 사각형 1”, “글자 “…””)으로 돌아갑니다.
- **숨기기**: 미리보기와 내보낸 파일에서 모두 빠집니다. 가려야 할 영역을 실수로 숨기지 않도록 주의하세요. 숨긴 항목만 남으면 내보내기가 꺼집니다.
- **잠금**: 잠긴 항목은 캔버스에서 선택·이동·방향키 이동·지우기·삭제가 되지 않고, **모두 지우기**와 그룹 이동에서도 제외됩니다. 목록에서는 계속 선택하고 이름을 바꿀 수 있습니다.
- 목록에서 행을 선택하면 캔버스에서도 선택되고, 우클릭하면 캔버스 우클릭과 같은 메뉴가 나옵니다.

## 프로젝트 저장·열기

**파일 → 프로젝트 저장…**(⌘S)은 영역·그림·시간·움직임 기록·그룹·순서를 `.bluraction` 파일(JSON)로 저장합니다. **프로젝트 열기…**(⇧⌘O)로 다시 열면 원본을 불러와 작업을 이어 갑니다. 위치는 창 크기와 무관하게 저장되므로 창 크기가 달라도 같은 자리에 놓입니다.

**템플릿처럼 쓰기**: **다른 영상에 프로젝트 적용…**은 저장한 프로젝트의 항목(위치는 화면 비율 기준, 시간·스타일 포함)을 고른 다른 영상이나 이미지에 적용해 엽니다. **프로젝트 항목 가져오기…**(⇧⌘I)는 지금 열린 파일에 프로젝트의 항목을 새 항목으로 더합니다. 이때 그룹은 새 그룹으로 복사되고, 영상 길이를 넘는 구간은 잘립니다. 가져오기는 ⌘Z 한 번으로 되돌립니다.

프로젝트에는 원본을 가리키는 정보만 들어 있고 원본은 복사하지 않습니다. 원본과 같은 폴더에 저장하면(기본값) 파일 이름만 기록하므로, 폴더째 옮기거나 공유해도 사용자 폴더 경로가 드러나지 않습니다. 다른 폴더에 저장하면 원본의 전체 경로를 기록합니다. 원본을 찾을 수 없으면 열 때 다시 고르면 됩니다. 열 때는 파일 크기와 내용 범위를 검사하며, 잘못된 파일은 열지 않고 안내합니다. 실행취소 기록은 저장되지 않습니다.

## 이미지

이미지에는 재생·움직임 기록이 없습니다. EXIF 방향은 픽셀에 적용하며 GIF는 첫 프레임만 정적 이미지로 편집합니다. 사진의 원본 EXIF·위치 메타데이터는 출력에 복사하지 않습니다. 이미지는 한 변 16,384픽셀, 전체 24MP(예: 6000×4000) 이하만 열 수 있습니다. 영상은 한 변 16,384픽셀, 전체 33,177,600픽셀(8K 7680×4320과 같은 화소 수) 이하만 엽니다.

## 검증

```bash
python3 scripts/verify_mac.py
```

각 검사 묶음을 별도 프로세스로 실행하고 실제 suite·Test run 완료 문구, 종료 코드, 입력·로그 해시를 확인합니다. 종료 코드0만 있거나 시간 제한을 넘으면 미완료로 기록하며 `.build/mac-verification-…/`에 로그와 보고서를 보존합니다. 한 묶음만 확인하려면 `--suite PortableProjectCompatibilityTests`처럼 지정합니다.

테스트는 합성 이미지·영상을 생성해 다음을 확인합니다.

- 실제 Core Image 픽셀(블러·모자이크·단색·채우기)
- EXIF 방향, 회전 영상, 오디오
- 영역·그림의 움직임 기록과 내보낸 프레임 일치
- 저장 충돌·취소·원본 보존
- AppKit 편집·지우개(시간 기반·부분)·스포이드·그룹·순서·글자·창 크기·실행취소
- 프로젝트 저장·열기·가져오기와 잘못된 프로젝트 거부
- 레이어 이름·숨기기·잠금, 여러 줄 글자·배경, 그룹 크기·복제, 타임라인 기록 시점·구간 끌기
- 움직이는 대상의 Vision 자동 추적(합성 영상)

영상 fixture 생성에 `ffmpeg`가 필요합니다. macOS 미디어 서비스와 WindowServer에 접근할 수 있는 로컬 사용자 환경에서 실행하세요. Swift Testing 매크로 경로는 스크립트가 Command Line Tools에서 찾습니다.

Finder에서 실제로 끌어놓는 OS 드래그 동작은 자동 테스트가 대신하지 못합니다. 테스트는 Finder와 같은 형식의 파일 정보로 창의 드롭 처리를 실행해 첫 화면 표시와 종횡비를 확인합니다.

코드 구성은 다음과 같습니다.

- 공용 합성(가리기·그리기·지운 부분): `BlurRenderer.swift`, `DrawingAnnotation.render(in:time:)`
- 시간별 위치 기록: `MotionTrack.swift`, `RegionEditing.swift`, `DrawingAnnotation.swift`
- 프로젝트 파일: `ProjectFile.swift`
- 자동 추적: `ObjectTracker.swift` (Vision `VNTrackObjectRequest`)
- 이미지·영상 저장: 각 Exporter

Python `scripts/blur_action.py`는 초기 CLI 실험 도구이며 앱 자체 검증을 대신하지 않습니다.

## 배포 상태

앱은 ad-hoc 서명만 되어 있습니다. 직접 빌드한 Mac에서는 실행되지만, 빌드한 앱을 다른 Mac으로 복사하면 Gatekeeper가 차단합니다(`spctl --assess` 결과 rejected). 다른 사람에게 앱 파일로 배포하려면 Apple Developer ID 서명과 공증(notarization)이 필요합니다. 소스에서 직접 빌드하면 각자의 Mac에서 실행할 수 있습니다.
